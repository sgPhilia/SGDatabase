# Glossary

Canonical definitions for terms used in the textbook. Definitions are introductory and may be refined in later chapters; specialized meanings should link to the chapter where they are developed formally.

| Term | Definition | First introduced |
|---|---|---|
| **Data** | Represented values or symbols that can be stored, transmitted, transformed, or processed. Their interpretation depends on conventions and context. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#2-data-information-representation-and-interpretation) |
| **Database** | An organized collection of data maintained for a purpose; product terminology may also use the word for a logical container. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#5-database-database-contents-and-dbms) |
| **Database management system (DBMS)** | Software that defines, stores, retrieves, updates, and manages databases through interfaces and rules. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#5-database-database-contents-and-dbms) |
| **Database system** | A DBMS, the databases it manages, client programs, and the operating environment needed to use them. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#5-database-database-contents-and-dbms) |
| **Database state** | The particular collection of values held under a schema at a given time; it is distinct from the schema's rules. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#22-schema-a-shared-description-of-structure) |
| **Database instance** | The actual values represented under a schema at a particular time; specialized models may define instance differently. | [V01-C02](docs/volume-01-foundations/part-01-data-and-computing/V01-C02-meaning-models-information.md#32-model-schema-and-instance) |
| **Bit** | A binary digit, represented abstractly as 0 or 1. | [V01-C04](docs/volume-01-foundations/part-01-data-and-computing/V01-C04-bits-bytes-types-encodings.md#1-from-values-to-bit-patterns) |
| **Byte** | An 8-bit unit in the common modern convention used in this book; a format must state units explicitly where ambiguity matters. | [V01-C04](docs/volume-01-foundations/part-01-data-and-computing/V01-C04-bits-bytes-types-encodings.md#1-from-values-to-bit-patterns) |
| **Information** | In ordinary database discussion, data interpreted in context for a question or decision. In information theory, related terms have formal probabilistic definitions; see Shannon information. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#2-data-information-representation-and-interpretation), [V01-C02](docs/volume-01-foundations/part-01-data-and-computing/V01-C02-meaning-models-information.md#6-semantic-information-and-shannon-information) |
| **Information loss** | The inability to recover distinctions discarded by a transformation such as rounding, sampling, truncation, or filtering. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#3-from-the-world-to-bits-and-back) |
| **Interpretation** | Rules that connect a representation to a meaning in a context. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#2-data-information-representation-and-interpretation) |
| **Model** | A purposeful structured representation of selected aspects of a domain, including concepts, relationships, and allowed operations. | [V01-C02](docs/volume-01-foundations/part-01-data-and-computing/V01-C02-meaning-models-information.md#3-models-purposeful-simplifications-of-a-domain) |
| **Representation** | A form in which data is expressed, such as text, an integer, a table row, or encoded bytes. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#2-data-information-representation-and-interpretation) |
| **Schema** | A declared description of data structure and rules, potentially including names, types, constraints, and relationships. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#22-schema-a-shared-description-of-structure) |
| **Semantic information** | An informal description of meaning in a domain and context; not a single universally accepted numerical measure and not the same quantity as Shannon entropy. | [V01-C02](docs/volume-01-foundations/part-01-data-and-computing/V01-C02-meaning-models-information.md#6-semantic-information-and-shannon-information) |
| **Shannon entropy** | A probability-distribution measure of uncertainty for a random variable, commonly expressed in bits when logarithms use base 2. Formal development: V01-C03. | [V01-C03](docs/volume-01-foundations/part-01-data-and-computing/V01-C03-information-theory-entropy-coding.md) |
| **Huffman code** | A variable-length prefix code built from symbol probabilities by repeatedly combining least-probable nodes; optimal among symbol-by-symbol prefix codes under the stated source model. | [V01-C03](docs/volume-01-foundations/part-01-data-and-computing/V01-C03-information-theory-entropy-coding.md#71-huffman-coding-walkthrough) |
| **Endianness** | The convention that determines the byte order of a multi-byte representation. | [V01-C04](docs/volume-01-foundations/part-01-data-and-computing/V01-C04-bits-bytes-types-encodings.md#5-byte-order-ordering-bytes-inside-multi-byte-values) |
| **Two's complement** | A fixed-width signed-integer representation in which the bit pattern for `−x` is the residue `2ⁿ−x` modulo `2ⁿ`, giving the range `−2ⁿ⁻¹` through `2ⁿ⁻¹−1`. | [V01-C04](docs/volume-01-foundations/part-01-data-and-computing/V01-C04-bits-bytes-types-encodings.md#4-signed-integers-and-twos-complement) |
| **Encoding** | A defined mapping from values or symbols to a representation, such as bits or bytes. | [V01-C04](docs/volume-01-foundations/part-01-data-and-computing/V01-C04-bits-bytes-types-encodings.md#1-from-values-to-bit-patterns) |
| **UTF-8** | A variable-width encoding form that maps Unicode scalar values to one-to-four-octet sequences under its specified constraints. | [V01-C04](docs/volume-01-foundations/part-01-data-and-computing/V01-C04-bits-bytes-types-encodings.md#7-text-characters-code-points-and-byte-encodings) |
| **Unicode scalar value** | A Unicode code point excluding the surrogate range; Rust `char` represents one scalar value. | [V01-C04](docs/volume-01-foundations/part-01-data-and-computing/V01-C04-bits-bytes-types-encodings.md#7-text-characters-code-points-and-byte-encodings) |
| **Grapheme cluster** | A sequence of code points treated as one user-perceived text unit under a defined boundary convention; it may contain more than one scalar value. | [V01-C04](docs/volume-01-foundations/part-01-data-and-computing/V01-C04-bits-bytes-types-encodings.md#7-text-characters-code-points-and-byte-encodings) |
| **Unicode normalization** | A specified transformation that maps text to a normalization form defined by Unicode; its equivalence and compatibility effects must match the application's contract. | [V01-C04](docs/volume-01-foundations/part-01-data-and-computing/V01-C04-bits-bytes-types-encodings.md#7-text-characters-code-points-and-byte-encodings) |
| **File** | An operating-system abstraction for named byte content and associated metadata; API semantics do not themselves define database transaction guarantees. | [V01-C05](docs/volume-01-foundations/part-01-data-and-computing/V01-C05-files-memory-persistent-storage.md#3-the-file-abstraction) |
| **Page cache** | An operating-system memory cache for file-backed data used to mediate many normal filesystem reads and writes. | [V01-C05](docs/volume-01-foundations/part-01-data-and-computing/V01-C05-files-memory-persistent-storage.md#4-the-page-cache-and-buffered-io) |
| **Durability** | A property that committed data survives a specified class of failures; the failure model and synchronization contract must be explicit. | [V01-C05](docs/volume-01-foundations/part-01-data-and-computing/V01-C05-files-memory-persistent-storage.md#5-what-does-written-mean) |
| **Process** | An executing program instance with an operating-system-managed address space and resources. | [V01-C06](docs/volume-01-foundations/part-01-data-and-computing/V01-C06-programs-processes-client-server.md#1-a-program-is-not-the-same-thing-as-a-running-service) |
| **Provenance** | Information about the origin, producer, or transformation history of a data value. | [V01-C02](docs/volume-01-foundations/part-01-data-and-computing/V01-C02-meaning-models-information.md#7-context-provenance-and-time) |
| **Referent** | The entity, event, or concept that a symbol is intended to describe. | [V01-C02](docs/volume-01-foundations/part-01-data-and-computing/V01-C02-meaning-models-information.md#2-meaning-is-relational-symbol-rule-context-referent) |
| **Thread** | An execution path scheduled within a process; threads commonly share their process's address space. | [V01-C06](docs/volume-01-foundations/part-01-data-and-computing/V01-C06-programs-processes-client-server.md#1-a-program-is-not-the-same-thing-as-a-running-service) |
| **Client-server** | An interaction pattern where a client requests a service from a server over a defined interface, often through a protocol. | [V01-C06](docs/volume-01-foundations/part-01-data-and-computing/V01-C06-programs-processes-client-server.md#3-client-server-request-flow) |
| **TCP byte stream** | An ordered, reliable byte-stream transport over a connection; application message boundaries are not preserved. | [V01-C06](docs/volume-01-foundations/part-01-data-and-computing/V01-C06-programs-processes-client-server.md#4-connections-and-byte-streams) |
| **Framing** | Application-protocol rules for determining the boundaries and interpretation of messages within a transport byte stream. | [V01-C06](docs/volume-01-foundations/part-01-data-and-computing/V01-C06-programs-processes-client-server.md#4-connections-and-byte-streams) |
| **Unicode code point** | A numbered position in the Unicode codespace; it is distinct from its encoded bytes and from a user-perceived grapheme. | [V01-C04](docs/volume-01-foundations/part-01-data-and-computing/V01-C04-bits-bytes-types-encodings.md#7-text-characters-code-points-and-byte-encodings) |
| **Syntax** | Rules governing whether a representation conforms to a permitted form or grammar. | [V01-C02](docs/volume-01-foundations/part-01-data-and-computing/V01-C02-meaning-models-information.md#21-syntax-type-and-semantics) |
| **Type** | A classification of values that constrains or defines available operations; a type name alone may not express domain meaning. | [V01-C02](docs/volume-01-foundations/part-01-data-and-computing/V01-C02-meaning-models-information.md#21-syntax-type-and-semantics) |
| **Value** | A particular represented item, such as `18.4`, `"ST-07"`, or a timestamp. | [V01-C01](docs/volume-01-foundations/part-01-data-and-computing/V01-C01-what-is-data.md#2-data-information-representation-and-interpretation) |
| **Vocabulary** | A shared set of terms and agreed definitions used within a domain or data exchange. | [V01-C02](docs/volume-01-foundations/part-01-data-and-computing/V01-C02-meaning-models-information.md#22-vocabulary-and-schema) |

When a term has several meanings across database products or research traditions, the relevant chapter states the local meaning and scope rather than silently changing this introductory definition.
